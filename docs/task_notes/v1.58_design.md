# v1.58 Large-Sample Persistent Memory Mainline Admission

## Goal

- Keep the persistent-memory runtime fixed and decide, on a large-sample real main experiment, whether `persistent_object_memory_v2` is strong enough to enter the main result line.
- Preserve paired compare discipline: same UID set, same query bank, same provider route, same budgets, same perception stack; only the object-memory logic variant differs.
- Reuse the existing result-layer admission, significance, export, and provenance tooling instead of introducing a parallel compare stack.

## residual_risks

- The large-sample compare is clean enough to admit, but both runs still show `admission_status=partial`, so a later larger run could still expose cost/latency/provider stability pressure.
- The current compare proves strict and memory-side gains on the frozen UID/sample contract, but it does not yet prove the same effect under a further widened UID pool or a different provider route.
- If strict gains flatten again on a wider run, the next bottleneck is more likely retrieval/decision consumption than perception or object-memory logic.
