# v1.51 Design + Implementation Note

## Single goal

- Explain weak real-pilot outcomes with repeated-run evidence, convert that evidence into conservative sample-size guidance, and export query uplift candidates without prematurely promoting weak queries into the main query bank.

## Scope boundary

- Keep all changes on benchmark orchestration, reporting sidecars, export, and provenance layers.
- Reuse existing telemetry, normalization, diagnosis, calibration, and query-strength outputs instead of creating a second evaluation stack.
- Do not modify runtime core files such as `pipeline.py`, `retriever.py`, `streaming/runner.py`, `eval_nlq.py`, or compare producers.

## residual_risks

- The real repeated pilot now has live-call proof, but the repeated evidence still points to mostly `small_sample_driven` instability, so the current `algorithm_no_effect_detected` conclusion remains weak.
- `sample_size_recommendation_status=range_only` is appropriate for the observed variance and `selected_uids_count=2`; the current run is not strong enough to lock a precise main-real sample target.
- Query uplift output is intentionally conservative: it exports candidates to strengthen later, not promotion-ready queries for the main bank.
- `paper_ready/snapshot.json` still lists `missing_tasks`; export closure is complete, but canonical main-result source coverage is not yet complete for all tasks.
